# クエストシステム

## 基本方針

クエストは目的が明確な行動とする。
ホームの「クエスト」から一覧を開く。

- クエストを実行すると1日進む。
- 成功・失敗にかかわらず、その日の行動は消費される。
- クエスト中に複数ノードを進んでも、追加の日数消費はない。
- クエスト終了、撤退、敗北後にホームへ戻ると翌日になる。
- ホームへ戻るとHP/SPは全回復する。

## クエスト種別

### メインクエスト

- 周回の本筋を進める。
- 重要イベント、ボス、エンディング条件に関係する。
- 解放条件や進行フラグを持つ。
- クリア状況が最終イベントやエンディング分岐に影響する。

### サブクエスト

- 装備、素材、所持金、経験値などを得るためのクエスト。
- 戦力強化や素材収集に関係する。
- エンディング分岐の主条件には基本しない。
- 特定キャラクターイベントや一部フラグの補助条件に使う余地はある。

## 進行形式

クエストは探索ノード型 + 軽い分岐ありとする。

- クエストを選ぶと探索ノードに入る。
- ノードマップで現在地と移動可能な次ノードを表示する。
- プレイヤーは表示されたノードから行き先を選ぶ。
- 基本は短い構造にし、一部に軽い分岐や寄り道を入れる。
- 分岐によって、戦闘数、報酬、素材、イベント、危険度が変わる。
- 終了ノードに到達するとクエスト成功。
- 撤退、敗北時はクエスト失敗扱い。
- 戦闘逃走に成功した場合、クエストは継続する。

## クエストとイベントの責務

クエストは探索構造を持つ。

- どのノードから始まるか。
- どのノードへ移動できるか。
- どこで戦闘するか。
- どこで宝箱があるか。
- 成功/失敗をどう判定するか。
- 再挑戦できるか。

イベントはゲーム状態の変更を持つ。

- お金付与。
- 素材付与。
- アイテム付与。
- 装備付与。
- 仲間加入/離脱。
- メイン進行度上昇。
- クエスト解放。
- うろつき場所解放。
- フラグ更新。
- エピローグ候補解放。

クエスト成功時は、終了ノード到達後にクリア時イベントを発生させる。
報酬や仲間加入などは、クエストデータではなくクリア時イベントの効果で処理する。

## クエスト状態

- 未解放
  - まだ一覧に出ない。

- 解放済み
  - 一覧に出て挑戦できる。

- 挑戦中
  - クエスト内にいる。

- クリア済み
  - 成功済み。

- 失敗済み
  - 1回限りクエストで失敗した状態。

## 再挑戦ポリシー

クエストごとに再挑戦ポリシーを持つ。

- `repeatable`
  - 何度でも再挑戦可。
  - 素材集め、通常サブクエスト、稼ぎ用。

- `untilClear`
  - 成功するまで再挑戦可。
  - メイン進行や重要クエスト向き。
  - 失敗しても再挑戦できるが、成功したらクリア済みになる。

- `once`
  - 成功・失敗に関わらず1回限り。
  - イベントクエスト、キャラクターイベント、分岐クエスト向き。
  - 成功したらクリア済み、撤退・敗北したら失敗済みになる。

## クエスト結果

- 成功
  - 終了ノードに到達。
  - クエストクリアイベントを発生させる。
  - クエストクリアフラグが立つ。

- 撤退
  - 失敗扱い。
  - 取得済み報酬は持ち帰れる。
  - 成功報酬は得られない。

- 敗北
  - 失敗扱い。
  - 取得済み報酬は持ち帰れる。
  - 成功報酬は得られない。

- 逃走
  - クエスト失敗にはしない。
  - 戦闘ノード側の設定に従い、ノード処理済みまたは未処理として扱う。
  - 逃走した戦闘の経験値・お金・素材などは得られない。
  - クエスト探索を継続する。

## 撤退

- クエスト中、プレイヤーはいつでも撤退を選べる。
- 撤退するとクエストは失敗扱い。
- その日の行動は消費される。
- ホームへ戻る。
- 日数が1日進む。
- HP/SPは全回復する。

## 報酬

- 宝箱を開けた時点で即取得。
- 戦闘に勝利した時点で経験値・お金・素材などを即取得。
- イベント報酬も付与タイミングで即取得。
- 撤退・敗北しても、すでに取得済みの報酬は失わない。
- クエスト成功時の追加報酬は、終了ノード到達後のクリア時イベント効果で付与する。

クエスト中に取得したアイテムや装備は、そのクエスト中に使用・装備可能。
ただし合成はホームメニューの機能なので、クエスト中には行わない。

## ノード種別

ノード種別は初期要件では以下に絞る。

- `start`
  - クエスト開始地点。
  - 最初に表示されるノード。

- `event`
  - 会話、選択肢、フラグ更新、演出。
  - 罠、回復、採取演出なども必要ならイベントで表現する。

- `battle`
  - 通常戦闘、強敵戦、ボス戦を設定で分ける。
  - 勝利時は次ノードへ進む。
  - 敗北時はクエスト失敗扱い。
  - 逃走成功時は、戦闘ノード側の設定に従って探索を継続する。

- `treasure`
  - アイテム、素材、装備、お金などを即取得する。
  - 採取も宝箱ノードの一種として扱う。
  - 表示名や演出で「採取」「調査」「拾得」などに見せ分ける。

- `end`
  - 到達するとクエスト成功。
  - クリア時イベントを発生させる。

## 分岐と接続

- 分岐専用ノードは作らない。
- 各ノードが複数の接続先を持てるようにする。
- プレイヤーは移動可能な接続先から次のノードを選ぶ。
- 接続先ごとに表示名を持てる。
- 接続先ごとに条件を持てる。

### 接続条件

- 特定フラグが立っている。
- 特定アイテムを持っている。
- 特定キャラが加入している。
- 特定キャラが編成されている。
- 戦闘に勝利した。
- 宝箱を開けている。
- イベントで特定選択肢を選んだ。
- メイン進行度が一定以上。
- 日数/フェーズ条件を満たす。

### 条件未達時の表示

接続ごとに、条件未達時の表示方法を設定できる。

- `hidden`
  - 条件を満たすまで選択肢に出さない。
  - 隠し道、未発見ルート、特定フラグ後に出る道など。

- `disabled`
  - 表示するが選択不可。
  - 鍵が必要な扉、仲間が必要な道、危険度不足など。
  - 条件未達の理由を表示できる。

## 宝箱ノード

- 宝箱、採取、拾得、調査報酬などをまとめて扱う。
- クエストに入るたびに取得可能。
- 同じクエストを再挑戦した場合でも再取得できる。
- 素材集めや金策に使える。
- ノード完了時に即取得。
- 撤退・敗北・逃走しても取得済み報酬は失わない。

レア装備や一品物を出したい場合は、宝箱ノードではなくイベントノードにして、イベント側でフラグ管理する。

## 戦闘ノード

- クエストに入るたびに戦闘が発生する。
- 同じクエストを再挑戦した場合でも再戦する。
- 戦闘勝利時に経験値・お金・素材などを即取得する。
- 戦闘敗北時はクエスト失敗扱い。
- 戦闘逃走成功時はクエスト失敗にせず、探索を継続する。
- 逃走成功時、その戦闘の経験値・お金・素材などは得られない。
- ボス戦も、再挑戦可能なクエストでは毎回発生する。
- 一品物や重要撃破フラグは、戦闘ノード自体ではなくクリア時イベントやイベント効果で管理する。

### 戦闘ノードの逃走設定

戦闘ノード、または `BattleData` に以下を持たせる。

- `canEscape`
  - 逃走可能か。

- `escapeCountsAsClear`
  - 逃走成功時に、その戦闘ノードを処理済みにするか。

通常戦闘:

```text
canEscape = true
escapeCountsAsClear = true
```

- 逃げられる。
- 逃げたらノード処理済み。
- 先へ進める。

ボス戦・重要戦闘:

```text
canEscape = false
```

- 逃げられない。
- 勝利しないと進めない。

突破必須の敵:

```text
canEscape = true
escapeCountsAsClear = false
```

- 逃げることはできる。
- ただしノードは未処理のまま。
- 先へ進むには倒す必要がある。

## データ構造

### QuestData

- `questId`
  - 一意ID。

- `title`
  - 表示名。

- `questType`
  - `main`
  - `sub`

- `description`
  - 概要テキスト。

- `unlockConditions`
  - 解放条件。

- `retryPolicy`
  - `repeatable`
  - `untilClear`
  - `once`

- `difficulty`
  - クエスト選択画面に表示する難度。
  - 数値または段階表示で扱う。

- `sortOrder`
  - クエスト一覧での表示順。

- `startNodeId`
  - 開始ノードID。

- `clearEventId`
  - 終了ノード到達時に発生するクリアイベントID。

- `failureEventId`
  - 失敗時に発生するイベントID。任意。

- `nodes`
  - クエスト内ノード一覧。

### QuestDataに持たせないもの

- `dayCost`
  - クエストは一律で1日消費するため、初期要件では持たせない。

- `recommendedLevel`
  - 初期要件では難度表示に集約する。

- `rewardHint`
  - クエスト選択画面には報酬ヒントを表示しない。

- `startConfirmText`
  - 開始確認文は共通文言を使う。

### QuestNodeData

- `nodeId`
  - ノードID。

- `nodeType`
  - `start`
  - `event`
  - `battle`
  - `treasure`
  - `end`

- `title`
  - ノード表示名。

- `description`
  - ノード説明。

- `position`
  - ノードマップ上の表示位置。

- `eventId`
  - イベントノード用。任意。

- `battleId`
  - 戦闘ノード用。任意。

- `treasureRewards`
  - 宝箱ノード用。任意。

- `connections`
  - 接続先一覧。

### QuestNodeDataに持たせないもの

- `iconType`
  - ノードアイコンは `nodeType` から自動で決める。

- `autoComplete`
  - ノード完了はノード種別ごとの標準処理で扱う。

- `isRepeatable`
  - 宝箱や戦闘はクエストに入るたび再取得・再戦できるため、初期要件では個別に持たせない。

- `onEnterEventId`
  - 到達時イベントは `event` ノードで表現する。

- `clearConditions`
  - 初期要件ではノード種別ごとの標準処理で扱う。

### QuestNodeConnection

- `toNodeId`
  - 移動先ノードID。

- `label`
  - 選択肢表示名。

- `conditions`
  - 接続条件。

- `lockedDisplay`
  - `hidden`
  - `disabled`

- `lockedReason`
  - 選択不可時の理由表示。

- `sortOrder`
  - 接続先一覧での表示順。
