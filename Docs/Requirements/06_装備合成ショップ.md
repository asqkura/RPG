# 装備・合成・ショップ

## 装備

装備は戦闘攻略の主な要素とする。
エンディング分岐の主条件には基本しない。

### 装備スロット

- 武器: 1枠
- 防具: 1枠
- アクセサリ: 2枠

### 装備制限

- 武器はキャラクター、または武器タイプによる装備制限を持つ。
- 防具は基本的に全員装備可能。
- アクセサリは基本的に全員装備可能。
- 主人公は全武器タイプを装備可能。
- 仲間はキャラクターごとに装備可能な武器タイプを設定する。
- 仲間の装備可能武器は原則として1キャラにつき2種類まで。

## 武器タイプ

- 剣
  - 斬属性。
  - バランス型。

- 短剣
  - 斬属性。
  - 素早さ・会心・状態異常寄り。

- 斧
  - 斬/打寄り。
  - 高火力・低速型。

- 槍
  - 突属性。
  - 安定した攻撃、隊列や先制補正と相性がよい。

- 弓
  - 突属性。
  - 後衛向け、命中・補助・状態異常寄り。

- 杖
  - 打/魔法寄り。
  - 魔法、回復、補助スキルと相性がよい。

## 主人公の武器

- 主人公は剣、短剣、斧、槍、弓、杖をすべて装備可能。
- 武器タイプによって役割を変えられる。
- 仲間編成に合わせて不足役割を補う。
- 主人公専用の得意武器は現時点では設定しない。

## 仲間の武器タイプ例

- 物理アタッカー: 剣 / 斧
- 魔法アタッカー: 杖 / 短剣
- ヒーラー: 杖 / 弓
- タンク: 剣 / 槍
- サポーター: 弓 / 杖
- スピード型: 短剣 / 弓

## 装備スキル

- 装備にスキルが設定されている場合、その装備中だけ使用できる。
- 装備を外すと、そのスキルは使用できなくなる。
- 装備している武器、防具、アクセサリ2枠のスキルはすべて使用可能。
- 装備スキル用の別セット枠は作らない。
- キャラクター固有スキルと装備スキルは、戦闘中のスキル一覧にまとめて表示する。

### 装備スキル構造

装備スキルは固定スキルとランダムスキル候補に分ける。

```text
baseSkillIds
randomSkillPool
```

- `baseSkillIds`
  - 装備に固定で付くスキル。
  - 装備すれば必ず使える。
  - 装備の個性や役割を決める。

- `randomSkillPool`
  - 装備ごとに設定されたランダムスキル候補。
  - 入手/合成時に候補から抽選される。
  - 装備ごとに付く可能性があるスキルを制限できる。
  - `randomSkillPool` が空の場合、ランダムスキルは付与されない。

## 装備個体差

装備強化は初期要件では採用しない。
`+1`, `+2` のような強化値は持たず、装備の性能は基本データと入手時のランダム性能で決まる。

- 同じ装備でも、入手・合成時にレアリティとランダム性能が抽選される。
- ランダム性能は周回内のみ有効。
- 周回終了時に装備はリセットされる。
- 装備図鑑はないため、個体差の記録は残さない。
- 基本性能は装備データで固定。
- ランダム性能は追加補正として扱う。

### レアリティ

装備は表示・整理用の `rarity` を持つ。
レアリティはランダム補正数とランダムスキル付与率に影響する。

- `common`
- `rare`
- `epic`
- `legendary`

強さはステータス補正、装備スキル、属性、耐性、合成Lvで決まる。
レアリティそのものはダメージ計算や性能補正には直接使わない。

### レアリティ抽選

- 装備のレアリティは入手時に抽選される。
- 合成入手では、合成レベルに応じたレアリティテーブルを使う。
- 店売り、宝箱、イベント入手では基本レアリティテーブルを使う。
- 固定レアリティや個別テーブルは初期要件では扱わない。

基本レアリティテーブル:

| rarity | 確率 |
| --- | ---: |
| common | 70% |
| rare | 25% |
| epic | 5% |
| legendary | 0% |

合成時レアリティテーブル:

| 合成Lv | common | rare | epic | legendary |
| --- | ---: | ---: | ---: | ---: |
| Lv1 | 75% | 23% | 2% | 0% |
| Lv2 | 65% | 30% | 5% | 0% |
| Lv3 | 55% | 35% | 9% | 1% |
| Lv4 | 45% | 40% | 13% | 2% |
| Lv5 | 35% | 45% | 17% | 3% |

### ランダム補正枠

ランダム補正枠では以下が付与される。

- ステータス補正
- 属性耐性
- 状態異常耐性
- 弱体耐性

対象ステータス:

- HP
- 攻撃
- 魔力
- 防御
- 素早さ
- 会心率

対象外:

- SP

数値幅:

- HP: `+10〜+25`
- 攻撃 / 魔力 / 防御 / 素早さ: `+3〜+8`
- 会心率: `+3〜+8%`
- 属性耐性: `+10%`
- 状態異常耐性: `+10%`
- 弱体耐性: `+10%`

同じ装備に同じ補正種別が複数付くことを許可する。

例:

```text
攻撃 +5
攻撃 +7
合計 攻撃 +12
```

### ランダム補正数

| rarity | ランダム補正数 |
| --- | --- |
| common | 0〜1個 |
| rare | 1個 |
| epic | 1〜2個 |
| legendary | 2〜3個 |

### ランダムスキル枠

- ランダムスキル枠は、ランダム補正枠とは別に扱う。
- ランダムスキルは装備ごとの `randomSkillPool` から抽選する。
- 付く場合は1個。
- `randomSkillPool` が空の場合は付与しない。

| rarity | ランダムスキル付与確率 |
| --- | ---: |
| common | 0% |
| rare | 30% |
| epic | 70% |
| legendary | 100% |

## EquipmentData

```text
equipmentId
name
description
iconSprite
equipmentType
weaponType
statModifiers
attributeResistances
statusResistance
debuffResistance
baseSkillIds
randomSkillPool
allowedRandomModifierTypes
equippableBy
price
unsellable
sortOrder
```

### 項目

- `equipmentId`
  - 一意ID。

- `name`
  - 表示名。

- `description`
  - 説明文。

- `iconSprite`
  - 装備アイコンSprite参照。
  - 装備一覧、ショップ、合成結果、入手表示で使用する。

- `equipmentType`
  - `weapon`
  - `armor`
  - `accessory`

- `weaponType`
  - 武器の場合のみ使用する。
  - 剣 / 短剣 / 斧 / 槍 / 弓 / 杖。
  - 通常攻撃属性は武器タイプから決定する。

- `statModifiers`
  - HP / SP / 攻撃 / 魔力 / 防御 / 素早さ / 会心率。

- `attributeResistances`
  - 属性耐性。

- `statusResistance`
  - 状態異常耐性。

- `debuffResistance`
  - 弱体耐性。

- `baseSkillIds`
  - 固定装備スキル。

- `randomSkillPool`
  - ランダムスキル候補。

- `allowedRandomModifierTypes`
  - その装備に付与されうるランダム補正候補。
  - 空の場合は、装備種別ごとの標準候補を使う。

- `equippableBy`
  - 装備可能キャラクター、または装備可能条件。

- `price`
  - 購入価格。

- `unsellable`
  - `true` の場合は売却不可。

- `sortOrder`
  - 装備一覧での表示順。

### EquipmentDataに持たせないもの

- `equipSoundEffectId`
  - 装備変更SEは画面または共通処理側で扱う。

- `obtainSoundEffectId`
  - 入手SEは入手処理側で扱う。

- `rarityBase`
  - レアリティは入手時に抽選されるため、基本データには持たせない。

- `randomModifierCountOverride`
  - ランダム補正数はレアリティごとの標準ルールを使う。

- `sellPrice`
  - 売却価格は購入価格の50%を基本とする。

## アイテム分類

初期要件ではキーアイテムを作らない。
クエスト進行やイベント進行はフラグで管理する。

### 消耗品

- HP回復
- SP回復
- 毒回復
- 状態異常回復
- 煙玉

初期要件では以下を含めない。

- 戦闘不能回復
- HP/SP両方回復
- 攻撃上昇アイテム
- 防御上昇アイテム

### 素材

- 合成に使う。
- 合成レベルアップに使う。
- 売却可能にするかは別途決める。

### 装備

- 武器
- 防具
- アクセサリ

### キーアイテムなしの方針

- 扉の開放、条件達成、依頼進行などはフラグで表現する。
- プレイヤーに明示したい進行情報は、イベント文やクエスト説明で見せる。
- 将来的に必要になった場合のみ、キーアイテム分類を追加する。

## ItemData

消耗品と素材はアイテムデータとして扱う。
キーアイテムは初期要件では作らない。

```text
itemId
name
description
iconSprite
itemType
rank
price
unsellable
usableInBattle
usableInField
effects
sortOrder
useAnimationId
useSoundEffectId
```

### 項目

- `itemId`
  - 一意ID。

- `name`
  - 表示名。

- `description`
  - 説明文。

- `iconSprite`
  - アイテムアイコンSprite参照。
  - アイテム一覧、ショップ、合成結果、入手表示で使用する。

- `itemType`
  - `consumable`
  - `material`

- `rank`
  - 素材ランク。
  - ランク1〜4。
  - 消耗品では基本空にする。

- `price`
  - 購入価格。

- `unsellable`
  - `true` の場合は売却不可。

- `usableInBattle`
  - 戦闘中に使用可能か。
  - 素材では基本 `false`。

- `usableInField`
  - 探索中/キャンプで使用可能か。
  - 素材では基本 `false`。

- `effects`
  - 消耗品の効果。
  - HP回復、SP回復、毒解除、状態異常解除、逃走成功など。
  - 素材では基本空にする。

- `sortOrder`
  - アイテム一覧での表示順。

- `useAnimationId`
  - 使用時の演出ID。
  - 素材では基本空にする。

- `useSoundEffectId`
  - 使用時のSE ID。
  - 素材では基本空にする。

### ItemDataに持たせないもの

- `category`
  - 初期要件では持たせない。
  - 必要になった場合に、表示・絞り込み用の分類として追加する。

### 所持上限

- 消耗品は個別の `maxStack` を持たせない。
- 消耗品は全体で20個まで所持可能とする。
- 素材はスタック可能とし、初期要件では所持上限を設けない。

## 消耗品仕様

### 使用可能場面

消耗品は、アイテムごとに使用可能場面を持つ。

```text
usableInBattle: true / false
usableInField: true / false
```

使用場面の初期方針:

| 種類 | 戦闘中 | 探索中/キャンプ |
| --- | --- | --- |
| HP回復 | 可 | 可 |
| SP回復 | 可 | 可 |
| 毒回復 | 可 | 不可 |
| 状態異常回復 | 可 | 不可 |
| 煙玉 | 可 | 不可 |

毒、スタン、攻撃低下、防御低下、攻撃上昇、防御上昇は戦闘終了時に解除されるため、毒回復・状態異常回復は戦闘中のみ使用する。

### 所持制限

- 消耗品は合計20個まで所持可能。
- 同名消耗品は個数表示してよい。
- 所持上限判定は全消耗品の合計数で行う。
- 素材・装備はこの20個制限に含めない。
- 20個を超える場合は購入・取得できない、またはその場で破棄/入れ替え選択を行う。

## 合成

装備入手の中心は合成とする。
クエストやうろつきで素材を集め、合成で武器、防具、アクセサリを作る。

### 合成の基本

- 合成では日数は進まない。
- 必要素材やお金を消費して装備・アイテムを作る。
- 作成した装備・アイテムは、その周回内の所持品として扱う。

### 合成レベル

- 名称は `合成レベル`。
- 合成レベルは `Lv1` から開始する。
- 最大 `Lv5`。
- 指定された素材やお金を支払うことでレベルアップする。
- 合成レベルアップでは日数は進まない。
- 合成レベルが上がるほど、作れる装備・アイテムが増える。
- 周回開始時は基本的に `Lv1` に戻る。
- テスト用、デバッグ用の初期データでは、動作確認を優先して合成Lvや所持素材を任意に付与してよい。

### 合成レベルの段階イメージ

- Lv1: 初期装備、基本消耗品
- Lv2: 序盤強化装備、基本アクセサリ
- Lv3: 中盤装備、属性・耐性装備
- Lv4: 終盤装備、特殊効果付き装備
- Lv5: 最上位装備、隠し・高性能装備

### 合成レベルアップ方針

- 合成Lvを上げるには素材とお金が必要。
- 通常素材に加えて、フェーズや進行に対応したキー素材を要求する。
- キー素材は主にメインクエスト、重要サブクエスト、強敵戦などで入手する。
- キー素材を集めることが、クエストへ行く目的になる。
- 合成レベルアップ要求は、素材ランク合計ではなく具体的な素材名で指定する。
- Lv4までは自然に進めても届きやすい。
- Lv5は少し意識して素材集めをする必要がある。

### 素材カテゴリ

素材カテゴリは初期要件では `ItemData` に持たせない。
以下は素材名や用途を考えるための設計メモとする。

- 鉱石系
  - 武器、防具、金属系アクセサリに使う。

- 木材系
  - 弓、杖、軽装備、道具に使う。

- 皮/布系
  - 防具、軽装備、アクセサリに使う。

- 魔石系
  - 魔法装備、属性装備、アクセサリに使う。

- 薬草系
  - 回復アイテム、補助アイテム、状態異常回復に使う。

- キー素材
  - 合成レベルアップや重要装備の解放に使う。

### 素材ランク

素材ランクはランク1〜4とし、4フェーズに対応させる。

- ランク1
  - 第1フェーズ中心。
  - 合成Lv1〜2で使う。
  - 基本素材。

- ランク2
  - 第2フェーズ中心。
  - 合成Lv2〜3で使う。
  - 序盤強化素材。

- ランク3
  - 第3フェーズ中心。
  - 合成Lv3〜4で使う。
  - 中盤素材。

- ランク4
  - 第4フェーズ中心。
  - 合成Lv4〜5で使う。
  - 終盤・高性能装備素材。

## 合成レシピ

### レシピ解放

- レシピは必要合成Lvを満たすと自動で表示・作成可能になる。
- クエストやイベントでのレシピ解放は初期要件では扱わない。
- 合成Lvを上げることが、そのまま作れるものの増加につながる。
- 特殊装備を作る場合も、まずは必要合成Lvと素材で制御する。

### 合成対象

- 武器
- 防具
- アクセサリー
- 消耗品

ショップは基本消耗品や基本装備の安定供給、合成は装備入手の中心と高性能消耗品の作成を担う。

### 合成結果

- 1回の合成につき1個作成する。
- 装備合成は、1回につき装備1個。
- 消耗品合成は、1回につき消耗品1個。
- 複数個まとめて作成は初期要件では扱わない。

### 消耗品合成の所持上限

- 合成で消耗品を作る場合も、消耗品合計20個制限に従う。
- 作成後に20個を超える場合、そのレシピは作成不可。
- 素材やお金は消費しない。
- 画面上では作成ボタンを無効化する。
- 作成不可理由の詳細表示は初期要件では必須にしない。
- 破棄/使用は別画面またはキャンプで行う。

### レアリティ抽選

- 装備合成では、作成時にレアリティ抽選とランダム性能抽選を行う。
- 消耗品合成では、レアリティ抽選を行わない。
- 消耗品は固定性能のアイテムを1個作成する。

### 合成確認

- 初期要件では、合成実行前の確認ダイアログは必須にしない。
- 合成ボタン押下時に素材・お金を消費し、作成物を付与してよい。
- 確認ダイアログは、操作ミス防止が必要になった段階で追加する。

確認ダイアログを追加する場合に表示するもの:

- 作成物
- 必要素材
- 消費金額
- 現在所持数
- 作成後の所持数

### レシピ表示

- 必要合成Lvを満たしたレシピは一覧に表示する。
- 素材やお金が足りない場合も表示する。
- 作成不可の場合は選択不可、または作成ボタンを無効化する。
- 不足している素材は、所持数/必要数で分かるように表示する。
- 不足金額や所持上限などの詳細理由表示は、初期要件では必須にしない。
- 未解放レシピは初期要件では表示しない。

### 合成カテゴリ

- 消耗品
- 武器
- 防具
- アクセサリー

### RecipeData

```text
recipeId
name
recipeType
requiredSynthesisLevel
ingredients
cost
resultType
resultItemId
sortOrder
```

#### 項目

- `recipeId`
  - 一意ID。

- `name`
  - 表示名。

- `recipeType`
  - `consumable`
  - `weapon`
  - `armor`
  - `accessory`

- `requiredSynthesisLevel`
  - 必要合成Lv。

- `ingredients`
  - 必要素材一覧。

- `cost`
  - 必要なお金。

- `resultType`
  - 作成物の種別。
  - `item`
  - `equipment`

- `resultItemId`
  - 作成されるアイテムまたは装備ID。

- `sortOrder`
  - レシピ一覧での表示順。

### RecipeDataに持たせないもの

- `resultCount`
  - 1回の合成につき1個作成で固定する。

- `isHidden`
  - 未解放レシピは初期要件では表示しないため、個別には持たせない。

- `unlockConditions`
  - レシピ解放は合成Lvのみで管理する。

- `category`
  - `recipeType` で扱う。

## ショップ

ショップは準備・補助・救済のための機能とする。

- 日数は進まない。
- 所持金を使って購入する。
- 不要なアイテムや装備を売却できる。
- 商品はフェーズ進行で増える。
- 合成レベルとは直接連動しない。

### 商品解放

- 第1フェーズ
  - 初期商品。

- 第2フェーズ
  - 序盤強化商品を追加。

- 第3フェーズ
  - 中盤商品を追加。

- 第4フェーズ
  - 終盤準備用の商品を追加。

### 販売するもの

- 消耗品
- 基本装備
- 一部素材

### 基本的に販売しないもの

- 最上位装備
- レア装備
- 重要イベント用アイテム
- 希少素材の大量販売

### 在庫

- 消耗品は在庫無制限。
- ただしプレイヤーの消耗品所持上限は合計20個。
- 素材は在庫有限。
- 装備は在庫有限。
- 有限在庫はフェーズ開始時に補充される。
- 補充タイミングは11日目、21日目、31日目。
- 1日ごとの補充はしない。

### ShopItemData

ショップに並ぶ商品設定を表す。
商品本体の性能や価格は `ItemData` / `EquipmentData` を参照する。

```text
shopItemId
availablePhase
itemType
itemId
stockType
stockCount
sortOrder
```

#### 項目

- `shopItemId`
  - ショップ商品設定の一意ID。

- `availablePhase`
  - 商品が並び始めるフェーズ。
  - 第1〜第4フェーズ。

- `itemType`
  - `item`
  - `equipment`

- `itemId`
  - 商品として販売するアイテムIDまたは装備ID。

- `stockType`
  - `unlimited`
  - `limited`

- `stockCount`
  - 有限在庫数。
  - `stockType = limited` の場合に使う。

- `sortOrder`
  - ショップ一覧での表示順。

#### ShopItemDataに持たせないもの

- `priceOverride`
  - 価格は `ItemData` / `EquipmentData` の `price` を使う。

- `restockPhase`
  - 有限在庫の補充タイミングは11日目、21日目、31日目で固定する。

### 売却

- 消耗品を売却可能。
- 素材を売却可能。
- 装備を売却可能。
- 売却時は確認を出す。
- 基本は売却可能とし、`unsellable = true` のものだけ売却不可にする。
- `unsellable` が未設定、または `false` なら売却可能。
- 売却不可のものは売却リストに出さない、または選択不可表示にする。
- 買い戻しは初期要件ではなし。

売却不可にする候補:

- キー素材
  - 森の魔核
  - 遺跡の歯車
  - 古竜の結晶
- イベント報酬装備
- 初期装備
- 売ると進行やバランスに影響するもの

### 売却価格

```text
売却価格 = 購入価格 × 0.5
```

- 小数は切り捨て。
- 購入価格が設定されていない非売品は、売却価格を個別設定するか売却不可にする。
