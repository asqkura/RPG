# キャラクターと成長

## パーティ・仲間

- 主人公は固定。
- 主人公は常にパーティにいる。
- 戦闘参加人数は、主人公 + 仲間3人の最大4人。
- 仲間総数は初期設計として6人。
- ゲーム開始時点では主人公 + 仲間1人で開始する。
- 編成では、加入済み仲間の中から参加メンバー3人を選ぶ。
- 控えメンバーは戦闘に参加しない。
- 控えメンバーは戦闘経験値を得ない。
- 育てたい仲間は編成して戦闘に参加させる必要がある。

## 仲間加入

仲間加入は複合方式とする。

- キャラクターごとに加入経路が異なる。
- 初期仲間や主要仲間はメイン進行で加入する。
- 任意仲間はうろつきイベントやクエストクリアで加入する。
- 隠し仲間は特定条件や複数フラグ達成で加入してもよい。
- 1周ですべての仲間を加入・育成・イベント完走する前提にはしない。
- 仲間加入はイベント効果で処理する。

## 仲間の役割

主人公は万能型とし、仲間6人は以下の役割を基本にする。

- 物理アタッカー
  - 攻撃・会心が高い。
  - 単体火力が得意。
  - 斬/打/突の主力。

- 魔法アタッカー
  - 魔力が高い。
  - 属性攻撃が得意。
  - 敵弱点を突く役割。

- ヒーラー
  - 回復・蘇生・状態異常回復が得意。
  - 継戦能力を支える。

- タンク
  - HP・防御が高い。
  - 味方を守る、防御系スキルを持つ。

- サポーター
  - 攻撃低下、防御低下、バフ、デバフが得意。
  - ボス戦や強敵戦で活躍する。

- スピード型
  - 素早さが高い。
  - 先制行動、会心、状態異常付与が得意。

## キャラクターイベント

キャラクターイベントは段階制 + フラグ制とする。

- キャラクターごとにイベント段階を持つ。
- 例: イベント1 → イベント2 → イベント3 → エピローグ条件達成。
- 各段階には発生条件を設定できる。
- 条件を満たした状態で、主に「うろつき」からイベントが発生する。
- 一部はクエスト同行やメイン進行で発生してもよい。

発生条件には以下を使える。

- 日数
- フェーズ
- うろつき場所
- メイン進行度
- 特定クエストのクリア
- 特定キャラの加入状態
- 特定キャラの編成状態
- 過去イベントの選択肢
- 戦闘勝敗
- 特定フラグ

## 成長

キャラクター成長はレベル制を基本とし、装備の影響も大きくする。

- 戦闘参加メンバーは経験値を得る。
- 経験値が一定値に達するとレベルアップする。
- レベルアップで基礎ステータスが上昇する。
- 控えメンバーは経験値を得ない。
- 周回ごとにレベル、装備、所持品はリセットされる。

## ステータス

- HP
- SP
- 攻撃
- 魔力
- 防御
- 素早さ
- 会心率

## CharacterData

```text
characterId
name
description
isProtagonist
baseStats
growthRates
equippableWeaponTypes
personalSkillIds
initialEquipment
defaultFormation
eventStageId
epilogueId
```

### 項目

- `characterId`
  - 一意ID。

- `name`
  - 表示名。

- `description`
  - 説明文。

- `isProtagonist`
  - 主人公かどうか。
  - 主人公は常にパーティに参加する。

- `baseStats`
  - Lv1時点の基礎ステータス。
  - HP、SP、攻撃、魔力、防御、素早さ、会心率。

- `growthRates`
  - レベルアップ時の成長傾向。
  - 役割ごとに伸びやすいステータスを設定する。

- `equippableWeaponTypes`
  - 装備可能な武器タイプ。
  - 主人公は剣、短剣、斧、槍、弓、杖をすべて装備可能。
  - 仲間は原則として1キャラにつき2種類まで。

- `personalSkillIds`
  - レベルアップや初期状態で使える固有スキルID。
  - 装備スキルはここには含めない。

- `initialEquipment`
  - 周回開始時、または加入時の初期装備。

- `defaultFormation`
  - 初期隊列。
  - `front` または `back`。

- `eventStageId`
  - キャラクターイベント段階を管理するID。

- `epilogueId`
  - 条件達成時に解放されるエピローグID。

## キャラクター状態

周回内セーブでは、CharacterDataそのものではなく、キャラクターごとの現在状態を保存する。

```text
characterId
isJoined
level
exp
currentHp
currentSp
formation
equippedWeaponInstanceId
equippedArmorInstanceId
equippedAccessoryInstanceIds
```

- `characterId`
  - 対象キャラクターID。

- `isJoined`
  - 現在の周回で加入済みかどうか。

- `level`
  - 現在レベル。

- `exp`
  - 現在経験値。

- `currentHp`
  - 現在HP。

- `currentSp`
  - 現在SP。

- `formation`
  - 現在隊列。
  - `front` または `back`。

- `equippedWeaponInstanceId`
  - 装備中の武器個体ID。

- `equippedArmorInstanceId`
  - 装備中の防具個体ID。

- `equippedAccessoryInstanceIds`
  - 装備中のアクセサリー個体ID一覧。
  - 最大2つ。

## 初期パーティ

周回開始時の加入状態は CharacterData には持たせない。
初期周回設定、または初期イベント効果で加入状態を作る。

初期要件では、周回開始時点で以下を加入済みとする。

- 主人公
- 初期仲間1人

## 新規開始時の初期状態

初期要件では、初期周回設定専用データは作らない。
新規開始時のゲーム開始処理で、周回内セーブデータの初期状態を生成する。

ゲーム開始処理で行うこと:

- 主人公を加入済みにする。
- 初期仲間1人を加入済みにする。
- 初期パーティを設定する。
- 初期隊列を設定する。
- 初期装備を付与し、装備させる。
- 初期アイテムを付与する。
- 初期クエストを解放する。
- 初期うろつき場所を解放する。
- 初期フラグを設定する。

将来的に初期状態の調整項目が増えた場合のみ、専用データ化を検討する。

## 隊列

隊列は前衛/後衛ありとし、キャンプ内の「隊列」から変更できる。

- 隊列変更では日数は進まない。
- 前衛は最低1人必要。
- 4人全員前衛は可能。
- 4人全員後衛は不可。
- 前衛は敵に狙われやすい。
- 後衛は敵に狙われにくい。
- 隊列による防御力上昇・被ダメージ増加は入れない。

## 隊列による攻撃補正

- 前衛からは、すべての武器を通常性能で使用できる。
- 後衛から剣、短剣、斧、槍で攻撃する場合、通常攻撃や近接スキルの威力が低下する。
- 弓は後衛からでも通常性能。
- 杖は後衛からでも通常性能。
- スキルごとに、必要なら隊列補正の例外を持てる。
- 敵には後衛攻撃、全体攻撃、貫通攻撃などを持たせられる。
